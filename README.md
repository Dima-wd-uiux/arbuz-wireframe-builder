# Arbuz Wireframe Builder

Codex-навык для превращения утвержденной структуры и текстов лендинга в серый схематичный прототип:

- адаптивный для компьютера, планшета и телефона;
- кликабельный;
- с меню, якорями, табами, FAQ, слайдером и модальной формой;
- без рабочей отправки данных;
- готовый к просмотру и загрузке на Netlify;
- с картой содержания, чтобы важные сведения не потерялись при верстке.

Навык нужен на этапе между утверждением текста и визуальным дизайном. Он не заменяет финальный дизайн, CMS или серверную разработку.

## Установка через Codex

Передайте человеку ссылку на репозиторий и попросите Codex:

```text
Используй $skill-installer и установи навык из
https://github.com/Dima-wd-uiux/arbuz-wireframe-builder
```

Codex автоматически обнаруживает новые навыки. Если навык не появился, перезапустите приложение. Актуальное устройство навыков и способы вызова описаны в [официальной документации OpenAI](https://learn.chatgpt.com/docs/build-skills).

### Если репозиторий приватный

Одной ссылки недостаточно: GitHub должен разрешить человеку доступ.

1. Узнайте GitHub username или email получателя.
2. Откройте репозиторий → **Settings** → **Collaborators** → **Add people**.
3. Отправьте приглашение и дождитесь, пока человек его примет.
4. После этого передайте ссылку и команду для `$skill-installer` либо `git clone`.

На Windows при первом клонировании приватного HTTPS-репозитория Git Credential Manager обычно откроет вход в GitHub в браузере. Каждый человек входит в собственный аккаунт. Не передавайте другому человеку свой пароль, personal access token или сохраненные учетные данные.

Важно: в приватном репозитории личного аккаунта GitHub приглашенный collaborator получает не только чтение, но и право отправлять изменения. Если нужен доступ только к зафиксированной версии без возможности push, отправьте ZIP-архив или перенесите репозиторий в GitHub Organization и выдайте роль чтения.

## Ручная установка

Codex ищет пользовательские навыки в `$HOME/.agents/skills`. На Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.agents\skills"
git clone https://github.com/Dima-wd-uiux/arbuz-wireframe-builder.git "$env:USERPROFILE\.agents\skills\arbuz-wireframe-builder"
```

Для обновления:

```powershell
cd "$env:USERPROFILE\.agents\skills\arbuz-wireframe-builder"
git pull
```

## Как использовать

Пример запроса:

```text
Используй $arbuz-wireframe-builder.

Во вложении структура и финальные тексты лендинга. Собери серый
кликабельный прототип, адаптируй его для мобильного экрана,
сделай демонстрационную форму и подготовь папку для Netlify.
Тексты не переписывай. Недостающие контакты оставь плейсхолдерами
и перечисли в handoff.md.
```

К задаче желательно приложить:

- порядок блоков;
- финальные заголовки и тексты;
- назначение кнопок;
- контакты или список отсутствующих контактов;
- требования к форме и интерактивным блокам;
- фотографии или описание мест под них;
- ссылку на Figma-конструктор, названия фреймов или скриншоты модулей;
- язык смыслового согласования и финальный язык страницы;
- прошлые правки, если они влияют на итоговую версию.

Полный рекомендуемый формат находится в `references/input-contract.md`.

## Создание проекта вручную

Если нужно получить чистую копию стартера без запуска навыка:

```powershell
python scripts/scaffold_prototype.py C:\path\to\new-prototype
```

Скрипт не перезаписывает непустую папку.

После заполнения проекта:

```powershell
python scripts/validate_prototype.py C:\path\to\new-prototype
```

Проверка ищет незамененные токены во всех текстовых файлах, битые якоря, отсутствующие локальные файлы, дублирующиеся ID, неверное число H1, отсутствие `noindex`, неподписанные поля, отсутствие адаптивных состояний и попытки реальной сетевой отправки формы. Она также требует `content-map.md` и `handoff.md`.

Если пользователь осознанно разрешил оставить один конкретный токен, перечислите его явно:

```powershell
python scripts/validate_prototype.py C:\path\to\new-prototype --allow-token PHONE_TEL
```

Флаг `--allow-placeholders` предназначен только для проверки незаполненного стартера.

## Локальный просмотр

В папке готового прототипа:

```powershell
python -m http.server 8080
```

Откройте `http://localhost:8080`.

## Netlify

Готовая папка не требует сборки. Ее можно загрузить через ручной deploy в Netlify или подключить отдельный Git-репозиторий проекта. `netlify.toml` публикует корень папки и добавляет `noindex`, чтобы схематичный прототип не попадал в поисковую выдачу.

## Развитие навыка

Правила и стартер меняются отдельно:

- новые требования процесса добавляются в подходящий файл `references/`;
- универсальные модули меняются в `assets/wireframe-starter/`;
- повторяемые проверки добавляются в `scripts/validate_prototype.py`;
- частное пожелание одного клиента не становится общим правилом, пока оно не доказало пользу для повторяемого процесса.

После изменений запустите проверку навыка и стартера, затем сделайте коммит с понятным описанием.
